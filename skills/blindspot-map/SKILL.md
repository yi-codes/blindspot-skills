# blindspot-map · 问之前先扫盲区

目标：在用户把问题交出去之前，用最少的篇幅补上他不知道自己不知道的部分，让他能问得更准、判断得更准。产出是一份盲区地图和一个更好的提问，不是答案本身；也不要写成教科书，只教到"能提问、能判断"为止。

它是提示，不是关卡。用户说"别扫了，直接答"，就直接答。

## 1. 定位起点

要教什么，取决于用户已经知道什么。上下文里看不出来时，只问必要的一两个问题：对这个领域熟悉到什么程度（第一次接触 / 了解一点 / 懂概念）、最终想用这个结果做什么决定、手上有没有"想要类似这样"的参考。能从对话、文件、代码库里查到的事实，自己去查，不要问用户。

## 2. 补足依据（按需）

领域变化快、或者你把握不大时，先联网查一轮，确认术语、现行做法、最新版本和已知的坑，再画地图。常识性领域可以跳过。在地图里标出哪些内容来自检索、哪些来自模型自身知识。

## 3. 画盲区地图

按下面的结构写，用不上的部分直接省略：

- **先说结论**：这件事里用户最需要知道的一两句话，最好配一个类比。
- **最少的术语**：只列后面会用到的词，每个词配一句白话解释。用户是行家时省略。
- **真正左右结果的 3–5 个决定**：这是盲区的核心。每个决定写清楚有哪几种选法、各自的代价，以及"在你的情况下，通常会怎么选"。决定不够 3 个就写实际的数量，不要凑。
- **常见的坑**：怎样做会失败，尤其是事后很难挽回的错误。
- **"好"长什么样**：优秀的结果通常具备什么特征，让用户能自己判断结果好坏；用户可能还不知道能做到多好。
- **哪些问题值得先问**：按"答案会多大程度改变用户的决定"排序。
- **改写后的提问**：一段用户可以直接拿去用的提问，把上面发现的盲区都考虑进去。

写法上结论先行，术语第一次出现时加白话解释，少用密集的表格和缩写。

有些标准用户说不出来，但看到了就知道对不对（风格、版式、语气、数据的样子）。这种情况不要靠追问，给两三个差别明显的小样例让用户挑，样例用完即弃，不要借机开始正式的工作。

## 4. 诚实标记把握程度

模型自己的盲区不会出现在模型自己画的地图上。明说哪些区域你比较有把握，哪些只了解皮毛或可能过时。对把握不大又会影响决定的部分，建议用独立来源核实（换模型、查原文、问懂行的人）；环境里有 cross-check skill 时可以直接接着用。

用户确定方向后，再进入正常的回答；给出重要结论后，可以接着用 answer-audit 做事后审计。
