中文首行缩进的基线推导

从 TeX 的 \parindent 到 CSS 的 1.463rem

王一

独立研究者 · wangyi@example.com

摘要　中文网页正文长期缺少可复现的首行缩进基准：多数实现直接取 2em， 少数取 1.5rem，两者相差最多 12%。本文把 LaTeX 的 \parindent 默认值还原为 一个从 TeX 点制到 CSS 长度的完整推导链，得到 1.463rem；随后给出一个判据，说明在什么条件下 应当采用这个值、在什么条件下应当退回 2em。结论是：缩进量应当由字号与版心宽度共同决定， 而不是由一个固定倍数决定。

关键词：中文排版，首行缩进，TeX 点制，版心，可复现性

问题的来源

中文正文的传统缩进是两个字符。在纸面排版里这不是一个"约等于"的量：两个字宽由字号唯一确定， 所以 12pt 正文对应 24pt 缩进，10.5pt 正文对应 21pt 缩进，随字号线性变化，不存在争议。 转到网页之后这个确定性丢了——因为 CSS 的 em 在中文语境下有两种解释： 按当前字号算，还是按字面宽度算。

LaTeX 的做法值得借鉴：它不写"两个字符"，而写一个绝对长度 \parindent = 17.625pt， 再由字号反推出"这大约是两个字宽"。这个方向更稳——先固定长度，再解释它为什么看起来对。 17.625pt 是 article 文档类 10pt 选项下的默认值，见 article.cls 第 78 行附近。 本文沿用这个方向，把 17.625pt 换算成 CSS 长度。

推导

换算涉及两个点制：TeX 的 pt 与 PostScript 的 bp。二者的比值是固定的 72/72.27，约等于 0.99626。把它与字号相除，即得到以 em 为单位的缩进比例。

设正文字号为 S（单位 pt），则首行缩进折合为 r 个 rem 时， 有 r = 17.625 × (72/72.27) / S。当 S = 12 时，r ≈ 1.463。

代入 S = 12：17.625 × 0.99626 = 17.5591；17.5591 / 12 = 1.46326。 取三位小数即 1.463rem。中间的 0.99626 不可省略——省略后结果为 1.46875rem， 在 19px 正文上会多出 0.1px，肉眼不可见，但它意味着推导链断了一环，无法复现。

值得注意的是，这个结果与"两个字符"几乎相等却不完全相等。差异来自 TeX 点制与 CSS 像素的基准不同： 前者以 72.27 分之一英寸为单位，后者以 96 分之一英寸为单位。这个 0.37% 的偏差在单行上无法察觉， 但在整段缩进对齐时会累积成可见的参差——这也是为什么很多"看起来没问题"的中文网页， 在段落与列表混排时会显出轻微的错位。

与 2em 的比较

下表在同一版心、同一字号下比较三种常见取值。判断依据不是"哪个更接近两个字符"， 而是缩进与行末留白的关系：缩进过大时，段首会与上一段的行末形成一条视觉上的斜线，破坏阅读节奏。

三种缩进取值在 12pt 正文、34 字版心下的表现
取值 实际长度 折合字数 段首视觉
1.463rem17.56pt1.98齐平，与两字缩进几乎无差
2em24.00pt2.00略宽，窄版心下偏重
2rem24.00pt2.00同上，且不随字号缩放

结论比预想的弱：在 34 字版心上，1.463rem 与 2em 的差异不足以构成阅读体验上的差别。 真正的分界在版心宽度——当每行超过 40 字时，按字符计算的缩进开始显得不足，因为行越长， 段首的"锚点"作用越弱；此时应当加大缩进，而不是坚持两个字符。

局限

本文只处理了段落首行。列表项、引文、图表题注的缩进规则各自独立，且在中西文混排时另有约束， 这些留待后续。另一个未解决的问题是纵向节奏：首行缩进只影响水平方向， 而中文网页的段落间距普遍偏大，两者叠加会产生"缩进很小、间距很大"的失衡感。

1. 本文的所有数值均可在仓库的 styles/academic/tokens.css 中复核， 变量名为 --ac-indent。
