# 风格索引

> 这个文件是**脚本生成的**，不要手改。
> 改风格的选择条件，去改那个风格 `DESIGN.md` 的 front matter，然后跑：
>
> ```bash
> python3 scripts/build-index.py
> ```

当前 **4** 个风格。

## 决定表

先定**这篇东西要让读者确认什么**，再在那一组里挑。

| 读者要确认的 | 职守 | 风格 |
|---|---|---|
| 「这人靠谱 / 这东西有品」 | 讲故事 | `editorial-serif` |
| 「这东西好用 / 这公司专业」 | 讲专业 | `swiss-grid` |
| 「这人技术过硬」 | 讲技术 | `terminal-mono` |
| 「这是给专业人做的」 | 讲工具 | `quiet-dark` |

## 全表

| 风格 | 职守 | 明暗 | 什么时候用 | 什么时候别用 | 画布 |
|---|---|---|---|---|---|
| **Editorial Serif** `editorial-serif` | 讲故事 | 浅色 | 长文、博客、白皮书、品牌故事、需要慢慢读的页面、杂志式栏目 | 工具界面、高密度数据、桌面应用、需要速度感的场景 | `#FBF8F3` |
| **Quiet Dark** `quiet-dark` | 讲工具 | 深色 | 桌面应用、编辑器面板、内部后台、Agent 对话界面、需要长时间注视的工具 | 营销落地页、长文阅读、品牌表达、打印 | `#0d0d0d` |
| **Swiss Grid** `swiss-grid` | 讲专业 | 浅色 | 落地页、产品页、案例研究、数据看板、B 端界面、需要显得专业的页面 | 长文阅读、需要情绪的场景、桌面应用外壳 | `#FFFFFF` |
| **Terminal Mono** `terminal-mono` | 讲技术 | 深色 | 技术文档、开发者工具、CLI 配套界面、以日志和代码为主体的页面 | 消费级产品、品牌表达、需要温度的场景 | `#0E1116` |

## 用法速查

```html
<!-- 引入某个风格 -->
<link rel="stylesheet" href="styles/<slug>/tokens.css">
<div class="ds-<slug>"> … </div>
```

变量前缀见每个风格 `tokens.css` 顶部的注释（`--ed-*` / `--sw-*` …）。

## 排他说明

`avoid` 里列的不是「不推荐」，是「**别用**」。
一个风格用在它 avoid 的场景里，出来的东西一定像模板 —— 因为它没为那个场景做过约束。

四个都排除了，说明这里该开一个新风格（见 `principles.md` §8），而不是硬套。
