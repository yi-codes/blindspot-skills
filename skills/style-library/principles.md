# 通用原则

> 这一页回答一个问题：**凭什么一个风格能"被 AI 精确执行"？**
> 答案不是形容词堆得够多，而是把风格拆成可验证的参数和可违反的约束。

---

## 1. 风格 = 参数 + 约束，不是形容词

"高级感""简约大气"这类词，人听了能想象，模型听了会各显神通。
能稳定复现的风格描述必须落到具体的量上：

| 别写 | 要写 |
|---|---|
| 干净、留白多 | 正文宽度 34 个汉字，段间距 24px，页边距 64px |
| 高级的深色 | 背景 `#0E1116`，文字 `#C9D1D9`，不用纯黑纯白 |
| 现代感字体 | Inter + Noto Sans SC，标题 700/正文 400，只两档 |
| 有点圆角 | 2px。不是 4，不是 8 |

**判断标准**：拿到这份描述，两个人（或两个模型）做出来的东西，肉眼看着应该基本一样。
做不到，说明还不够具体。

---

## 2. 一个画面只有一个主角

文字在说话的时候，装饰就闭嘴。

- 有彩色强调色，就不要同时有大标题动画
- 有强对比的图片，文字就要退成小字和灰字
- 有 3 级标题层级，就不要用 5 级

**检验方法**：眯着眼睛看，第一个跳进视野的东西，是不是你想让人看的那个？
不是，就是层级错了。

---

## 3. 颜色不超过三个家族（含中性色）

- 中性色一族（背景 / 表面 / 文字 / 分隔线，本质是一根灰阶）
- 一个强调色（主操作、可点击）
- 语义色（成功 / 警告 / 错误）—— 只在需要时局部出现，不算"家族"

超过三个，人眼就无法建立"哪个重要"的秩序，页面会变成调色板。

### 纯黑纯白什么时候可以用

我原来的说法是"不用纯黑纯白"，这是错的。**纯黑纯白本身没问题，问题是它需要别的东西撑着。**

看 Ollama 的例子（`references/ollama/`）：它全站用 `#000000` + `#FFFFFF`，效果非常干净。但它付了三个代价：

1. **只有一张连续的白纸**——零表面交替，不靠底色区分区域
2. **形状语言绝对统一**——所有交互元素都是 pill，没有一个例外
3. **全页只有一处深浅反转**——最高价档，仅此一处

这三件事只要缺一件，纯黑纯白就会露出廉价感。所以判断顺序是：**先问"有没有别的手段撑住它"，再决定用不用纯色。**

对比：`swiss-grid` 有 canvas / surface / surface-alt 三档表面，如果再用纯黑当文字色，底色层次会和文字打架。所以它用 `#111111`。

### WCAG 是底线，不是审美标准

`#A3A3A3` 在白底上只有 2.52:1 对比度（Tailwind 的 `neutral-400` 就是这个值，行业里到处在用）。按 AA 要求 4.5:1，它不合格。

我的处理：占位符和禁用态这类"最弱一级"文字，压到 3.0:1 以上（`#8F8F8F`，3.23:1）。理由是这个库要能被别人读，不只是被自己看。

**但不追求全站 4.5:1 以上**。全部拉满会让界面变成黑白分明的高对比，失去层次。分层本身有价值，前提是最弱那一层仍然可辨认。


---

## 4. 字号和字重：要么同级，要么跳一大截

层级靠**落差**，不靠**差异**。

- 字号：模数至少 1.25。17 → 18 → 19 是错的，17 → 21 → 26 才是对的
- 字重：只用两档（400 + 600/700）。加第三档 500，前两档的对比立刻失效
- 行高：字号越大，行高越紧（大字 1.1-1.25，正文 1.6-1.85）

---

## 5. 圆角、阴影、描边是"语言"，不是装饰

三种视觉手段，选一种作为主要分隔方式，其余退到辅助位置：

| 主要手段 | 气质 | 典型风险 |
|---|---|---|
| 1px 描边 | 精确、克制、文档感 | 太密会显得像表格 |
| 阴影 | 层级、浮起、卡片化 | 一用就"扁平化 Bootstrap" |
| 纯留白 | 高级、呼吸感 | 信息密度低，撑不起复杂页面 |

**混用是廉价感的主要来源**：一个页面里既有大圆角卡片、又有投影、又有硬边框，看着就乱。

---

## 6. 中文排版的六件事（这一节最容易出事）

1. **行高不能照搬西文**：西文 1.5 舒服，中文 1.5 会闷。正文从 1.7 起步，长文 1.85。
2. **中西文之间留 1/4 空格**：`2026 年`、`用 A7C2 拍`、`iPhone 17`。
3. **标点占一个汉字宽**：写 CSS 时 `text-spacing-trim` 未必生效，手动留白更可靠。
4. **避头尾**：句号、逗号不能出现在行首（`line-break: strict`）。
5. **不用首行缩进两字符**：网页上段落靠间距分隔，缩进是印刷习惯。
6. **字重别乱加**：中文字体 500 和 600 差别极小，用了等于没用。直接上 700。

---

## 7. 同一风格要能"双向翻译"

这份库每个风格都有两套出口：

- **`tokens.css`** → 网页 / UI 的直接实现
- **`prompt.md`** → 生图时的视觉参考

它们必须能互相对上。如果网页是暖纸白 + 赭红，生图却给了霓虹蓝紫，那不是两个渠道，是两个品牌。

**检验方法**：把网页截图和生图并排放，问"这两张是同一家公司做的吗"。答"是"，风格就成立。

---

## 8. 什么时候该新开一个风格，而不是改现有的

- 新场景需要违反现有风格的**硬约束**（比如要在深底上用圆角）→ 新开
- 只是调色板深浅、字号大小 → 改现有，别开新的
- 只是"这次想换个感觉" → 先别加，等第三次真的用到再加

**风格库的价值在少而准，不在多。** 二十个互相打架的风格，不如五个各有明确职守的。

---

## 9. 吸收外部风格：只拿能变成数值的东西

看到别人的设计觉得好，直接照搬形式是最常见的失败。失败有三种形态：

| 失败形态 | 表现 | 后果 |
|---|---|---|
| 抄配色不抄比例 | 拿了人家的颜色，但字号、间距全按自己的来 | 颜色对了，气质不对 |
| 抄组件不抄留白 | 抄了按钮和卡片，但页面比原版挤一倍 | 显得像廉价模板 |
| 抄风格不抄场景 | 把营销页的风格搬到文档上 | 两边都不对 |

**根因是同一个**：让人产生"好看"感觉的，往往不是那个看得见的东西，是它周围的一整套约束。

### 判据：这一条能不能写成数值？

拿到一份外部样本，逐条过一遍这个筛子：

- 能写成 `{token}` 或一条可检查规则的 → **吸收**
- 只能形容成"高级""未来感""有质感" → **留在 references 当灵感，不进 styles**
- 依赖品牌资产（logo、吉祥物、授权字体）→ **不吸收**，这是身份不是风格

### 吸收的三个去处

大部分情况是第 1 种，这是库能长大的正常方式：

1. **补进现有风格**——从 Claude 学到"墨色不用纯黑"，直接修 `editorial-serif` 的 `colors.ink`
2. **成为通用原则**——跨风格都成立的，写进这一页
3. **促成新风格**——只有当它**必须违反现有风格的硬约束**时才新开

### 一条反向纪律

**"弃"要写下来。**

每份 `references/*/NOTES.md` 都有一栏"弃"，记录你为什么**不**吸收某一条。这一栏比"取"更有价值——它记录的是判断力。半年后你只会想知道"我当初为什么没抄它"，而不会记得"我抄了什么"。

---

## 10. 别让工具替代判断

`./scripts/lint.py` 能查：token 引用是否有效、颜色是否与 CSS 一致、对比度是否达标、必备章节是否齐全。

它查不了：这个风格该不该存在、这个间距是不是对的、这个颜色是不是你想要的。

**lint 通过不等于设计成立。** 它是下限检查，不是质量证明。真正的验收永远只有一条：把它做出来，自己看一眼，问"这是我想要的吗"。
