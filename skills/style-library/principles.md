# 通用原则

> 这一页回答一个问题：**凭什么一个风格能"被 AI 精确执行"？**
> 答案不是形容词堆得够多，而是把风格拆成可验证的参数和可违反的约束。

---

## 1. 风格 = 参数 + 约束，不是形容词

"高级感""简约大气"这类词，人听了能想象，模型听了会各显神通。
能稳定复现的风格描述必须落到具体的量上：

| 别写 | 要写 |
|---|---|
| 干净、留白多 | 正文宽度 34 个汉字，段间距 24px，页边距 64px |
| 高级的深色 | 背景 `#0E1116`，文字 `#C9D1D9`，不用纯黑纯白 |
| 现代感字体 | Inter + Noto Sans SC，标题 700/正文 400，只两档 |
| 有点圆角 | 2px。不是 4，不是 8 |

**判断标准**：拿到这份描述，两个人（或两个模型）做出来的东西，肉眼看着应该基本一样。
做不到，说明还不够具体。

---

## 2. 一个画面只有一个主角

文字在说话的时候，装饰就闭嘴。

- 有彩色强调色，就不要同时有大标题动画
- 有强对比的图片，文字就要退成小字和灰字
- 有 3 级标题层级，就不要用 5 级

**检验方法**：眯着眼睛看，第一个跳进视野的东西，是不是你想让人看的那个？
不是，就是层级错了。

---

## 3. 颜色不超过三个家族（含中性色）

- 中性色一族（背景 / 表面 / 文字 / 分隔线，本质是一根灰阶）
- 一个强调色（主操作、可点击）
- 语义色（成功 / 警告 / 错误）—— 只在需要时局部出现，不算"家族"

超过三个，人眼就无法建立"哪个重要"的秩序，页面会变成调色板。

### 纯黑纯白什么时候可以用

我原来的说法是"不用纯黑纯白"，这是错的。**纯黑纯白本身没问题，问题是它需要别的东西撑着。**

看 Ollama 的例子（`references/ollama/`）：它全站用 `#000000` + `#FFFFFF`，效果非常干净。但它付了三个代价：

1. **只有一张连续的白纸**——零表面交替，不靠底色区分区域
2. **形状语言绝对统一**——所有交互元素都是 pill，没有一个例外
3. **全页只有一处深浅反转**——最高价档，仅此一处

这三件事只要缺一件，纯黑纯白就会露出廉价感。所以判断顺序是：**先问"有没有别的手段撑住它"，再决定用不用纯色。**

对比：`swiss-grid` 有 canvas / surface / surface-alt 三档表面，如果再用纯黑当文字色，底色层次会和文字打架。所以它用 `#111111`。

### WCAG 是底线，不是审美标准

`#A3A3A3` 在白底上只有 2.52:1 对比度（Tailwind 的 `neutral-400` 就是这个值，行业里到处在用）。按 AA 要求 4.5:1，它不合格。

我的处理：占位符和禁用态这类"最弱一级"文字，压到 3.0:1 以上（`#8F8F8F`，3.23:1）。理由是这个库要能被别人读，不只是被自己看。

**但不追求全站 4.5:1 以上**。全部拉满会让界面变成黑白分明的高对比，失去层次。分层本身有价值，前提是最弱那一层仍然可辨认。


---

## 4. 字号和字重：要么同级，要么跳一大截

层级靠**落差**，不靠**差异**。

- 字号：模数至少 1.25。17 → 18 → 19 是错的，17 → 21 → 26 才是对的
- 字重：只用两档（400 + 600/700）。加第三档 500，前两档的对比立刻失效
- 行高：字号越大，行高越紧（大字 1.1-1.25，正文 1.6-1.85）

---

## 5. 圆角、阴影、描边是"语言"，不是装饰

三种视觉手段，选一种作为主要分隔方式，其余退到辅助位置：

| 主要手段 | 气质 | 典型风险 |
|---|---|---|
| 1px 描边 | 精确、克制、文档感 | 太密会显得像表格 |
| 阴影 | 层级、浮起、卡片化 | 一用就"扁平化 Bootstrap" |
| 纯留白 | 高级、呼吸感 | 信息密度低，撑不起复杂页面 |

**混用是廉价感的主要来源**：一个页面里既有大圆角卡片、又有投影、又有硬边框，看着就乱。

---

## 6. 中文排版的六件事（这一节最容易出事）

1. **行高不能照搬西文**：西文 1.5 舒服，中文 1.5 会闷。正文从 1.7 起步，长文 1.85。
2. **中西文之间留 1/4 空格**：`2026 年`、`用 A7C2 拍`、`iPhone 17`。
3. **标点占一个汉字宽**：写 CSS 时 `text-spacing-trim` 未必生效，手动留白更可靠。
4. **避头尾**：句号、逗号不能出现在行首（`line-break: strict`）。
5. **不用首行缩进两字符**：网页上段落靠间距分隔，缩进是印刷习惯。
6. **字重别乱加**：中文字体 500 和 600 差别极小，用了等于没用。直接上 700。

---

## 7. 同一风格要能"双向翻译"

这份库每个风格都有两套出口：

- **`tokens.css`** → 网页 / UI 的直接实现
- **`prompt.md`** → 生图时的视觉参考

它们必须能互相对上。如果网页是暖纸白 + 赭红，生图却给了霓虹蓝紫，那不是两个渠道，是两个品牌。

**检验方法**：把网页截图和生图并排放，问"这两张是同一家公司做的吗"。答"是"，风格就成立。

---

## 8. 什么时候该新开一个风格，而不是改现有的

- 新场景需要违反现有风格的**硬约束**（比如要在深底上用圆角）→ 新开
- 只是调色板深浅、字号大小 → 改现有，别开新的
- 只是"这次想换个感觉" → 先别加，等第三次真的用到再加

**风格库的价值在少而准，不在多。** 二十个互相打架的风格，不如五个各有明确职守的。

---

## 9. 吸收外部风格：只拿能变成数值的东西

看到别人的设计觉得好，直接照搬形式是最常见的失败。失败有三种形态：

| 失败形态 | 表现 | 后果 |
|---|---|---|
| 抄配色不抄比例 | 拿了人家的颜色，但字号、间距全按自己的来 | 颜色对了，气质不对 |
| 抄组件不抄留白 | 抄了按钮和卡片，但页面比原版挤一倍 | 显得像廉价模板 |
| 抄风格不抄场景 | 把营销页的风格搬到文档上 | 两边都不对 |

**根因是同一个**：让人产生"好看"感觉的，往往不是那个看得见的东西，是它周围的一整套约束。

### 判据：这一条能不能写成数值？

拿到一份外部样本，逐条过一遍这个筛子：

- 能写成 `{token}` 或一条可检查规则的 → **吸收**
- 只能形容成"高级""未来感""有质感" → **留在 references 当灵感，不进 styles**
- 依赖品牌资产（logo、吉祥物、授权字体）→ **不吸收**，这是身份不是风格

### 吸收的三个去处

大部分情况是第 1 种，这是库能长大的正常方式：

1. **补进现有风格**——从 Claude 学到"墨色不用纯黑"，直接修 `editorial-serif` 的 `colors.ink`
2. **成为通用原则**——跨风格都成立的，写进这一页
3. **促成新风格**——只有当它**必须违反现有风格的硬约束**时才新开

### 一条反向纪律

**"弃"要写下来。**

每份 `references/*/NOTES.md` 都有一栏"弃"，记录你为什么**不**吸收某一条。这一栏比"取"更有价值——它记录的是判断力。半年后你只会想知道"我当初为什么没抄它"，而不会记得"我抄了什么"。

### 调色板不是设计语言（这一节是踩出来的）

`soft-pastel` 是第一个从**纯配色方案**里做的风格（Catppuccin）。做的时候撞上两个坑，值得记下来：

**坑一：配色方案不回答"层级怎么分"。**

Catppuccin 给了 26 个色和它们的名字（base / mantle / crust / surface0…），但没说"卡片该用哪个、和底差多少才够"。Latte 的 mantle 和 base 之间只有 **1.04:1** —— 用它做卡片，卡片直接消失。"零边框零阴影、靠明度分层"这句话在浅色版执行不了，必须补一条 1px 描边。这条描边不是美学选择，是配色没给够信息。

**坑二：配色的"色"不等于"能写字"。**

14 个 accent 看起来都很温和，实际在 Latte 上只有 2 个过了 4.5:1。剩下 12 个只能做填充和图标。**这一步必须自己算**，配色方案不会告诉你。而且失败时它"看起来还行"——那正是最危险的地方。

所以从配色方案做风格，规则是这样的：

| 来源给了什么 | 你能声称什么 |
|---|---|
| 色值 | 「颜色可复现」 |
| 色值 + 组件 + 尺寸 | 「整份都可复现」 |
| 只有色值 | 「颜色是它的，形状是我补的」← 必须写在文档第一段 |

第三个不超过一半，就别把这份文档写得像前两种。**读者有权知道哪些数是查得到的，哪些是我定的。**

## 10. 别让工具替代判断

`./scripts/lint.py` 能查：token 引用是否有效、颜色是否与 CSS 一致、对比度是否达标、必备章节是否齐全。

它查不了：这个风格该不该存在、这个间距是不是对的、这个颜色是不是你想要的。

**lint 通过不等于设计成立。** 它是下限检查，不是质量证明。真正的验收永远只有一条：把它做出来，自己看一眼，问"这是我想要的吗"。

## 11. AI 味儿是可枚举的（这一节来自 hallmark 的 70 条 gate）

判断"这份设计是不是机器做的"，靠感觉说不清。但它是可以列举的。

来源：`references/hallmark/`（[Nutlope/hallmark](https://github.com/Nutlope/hallmark)，55.6k★，专门反 slop 的 skill）。
它把"一看就是生成的"拆成了 70 多条具体特征，每条给"症状 → 修法"。下面只留对**界面类**产物有效的部分，落地页专用的（hero 高度、section 间距、订阅栏）在这里不适用。

### 11.1 唯一的真指标：Specificity

拿掉产品名，这份设计还站得住吗？

- **站得住** = 它不属于任何产品 = 它是模板 = 有 AI 味儿
- **站不住** = 它只属于这一个产品 = 它真的在设计

这不是修辞。检测方法很硬：**把 `DESIGN.md` 里的名字遮住，问"这份文档能不能套到另一个产品上"。能，就是废纸。**

反面样本在 `references/bergside-codex/DESIGN.md`——一份自称 Codex 风格的文档，
`primary: #000000`、`surface: #FFFFFF`、`neutral: #FFFFFF`（三个 token 撞成同一个白）、字体 Open Sans。
它格式完全合规，配色跟 Codex 没有一毛钱关系。

### 11.2 十二条"一眼假"

按出现频率排。左列是症状，右列是修法。

| # | 症状 | 修法 |
|---|---|---|
| 1 | **紫到蓝 / 紫到粉的渐变**，或者渐变文字（`background-clip: text`） | 一个主色，实底。这是第一号特征，没有例外 |
| 2 | **米色纸 + 高对比衬线标题 + 陶土/砖红点缀** | 换掉一个轴：先换点缀色，再换纸色，最后才换字体 |
| 3 | **标题前面那行"宣布下面是什么"的小字**（eyebrow / 比如标题上方一个 "CASE STUDY"） | 删掉试试。什么都不丢 → 它是装饰。要留就得是署名、`<time>`、文件名这类**带信息**的 |
| 4 | **全大写 + 字距拉开的小标签**（≤15px，`letter-spacing` >0.03em） | 正文同款字体，小一档，原样大小写，不拉字距 |
| 5 | **中点拼元信息**：`A · B · C`；**箭头粘在链接后面**：`了解更多 →`；**状态圆点当前缀** | 换行、分栏、细分隔线；动词当标签。一条里最多一个点 |
| 6 | **等宽字体当戏服**（非代码的标签、说明、表头用 mono） | 标签回到正文字体，小一档 |
| 7 | **三列等宽的「图标在上、标题在下」卡片**；卡片上一块圆角色块装图标 | 改不等宽不等高，图标内联进标题行 |
| 8 | **纯黑 `#000` / 纯白 `#fff` 当大面积底色** | 往主色偏一点，别用绝对值 |
| 9 | **框架默认色板**（Tailwind 的 indigo-500 / violet-600 / slate-900）直接当 token | 自己调一版 |
| 10 | **氛围光**：文字后面的光斑、模糊的彩色球、深色上一圈没有偏移的发光投影 | 实底或颗粒面；层级靠明度差和带偏移的投影 |
| 11 | **装饰性文字**：竖排旋转的标签、滚动提示、`BETA` 徽章、版本号、城市天气条 | 删。它说的是"我设计了"，不是任何事实 |
| 12 | **同一件事说四遍**（价格在 hero、每张卡、FAQ、页脚各来一次） | 一个事实只放在它干活的那一处 |

### 11.3 深色模式的三条硬规矩

这批是数值级的，直接能用：

1. **画布明度 L 12-18%，不许 `#000`；文字 L 92-96%，不许 `#fff`。**
   （`quiet-dark` 的 `#0d0d0d` / `#f7f7f7` 落在区间内，画布比下限还暗——因为 Codex 真的更黑，这是实测值不是估的。）
2. **层级靠明度，不靠投影。** 每升一层 +3~4% L，或者 `box-shadow: inset 0 0 0 1px` 画内描边。
   深色上的投影会变成灰雾或发光。
3. **正文字重减 50。** 深色底上的亮字视觉上更粗（光渗），所以浅色用 400 的地方，深色要用 350。
   **这条最容易漏**，四个风格里原来一处都没写。

### 11.4 豁免必须留痕

规则不是绝对的，但破例要付代价：

> 写 `/* waive 67 · 这个标签是真实文件名 · file.ts */` 这种形式——**哪一条、证据是什么、为什么这次不一样**。

三个否决条件：理由少于 24 个字符、是套话、或者跟别处的理由一字不差。
同一个豁免连着用三次，它就变成你的风格了，应该写进 `DESIGN.md` 而不是继续当例外。

**这条比规则本身重要。** 它把"例外"从随口一说，变成了一个要留痕的动作。

### 11.5 自查怎么用

写完一个页面/一个风格，按顺序问：

1. 遮住产品名，这份东西还属于这个产品吗？（11.1）
2. 十二条"一眼假"里有几条中了？中 3 条以上先别发布。（11.2）
3. 深色的画布、文字明度和正文字重，对了吗？（11.3）
4. 每一处破例，理由写下来了吗？（11.4）

**已知的自查结果（2026-11-16，第一次跑）**：

- `editorial-serif` 中 **#2**（米色 + 衬线 + 陶土红）。这就是它被评价"太普通"的准确原因。修法是换掉轴——先动点缀色。
- `showcase/codex.html` 中 **#3 / #4 / #5 / #8**，都是当场改掉的（见 git 记录）。
- `quiet-dark` 的深色画布和"层级靠明度"两条，跟 hallmark 的结论一字不差——两条独立路径撞到同一个答案，说明这两条是硬事实。
