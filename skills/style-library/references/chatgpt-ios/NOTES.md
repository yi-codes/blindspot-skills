## 它是什么

一份对 **ChatGPT iOS 客户端**的视觉拆解，手写的，有真实观察。
不是 Codex 桌面版——是**同一个设计语言的另一个surface**。这个区别很重要，见下面「弃」第一条。

## 取

### 1. 它验证了我从 app.asar 抠出来的值（最重要的收获）

两套来源、两种方法，撞上了同一批数字：

| 值 | 我从 `app.asar` 抠的 | 它从 iOS 拆的 | 判定 |
|---|---|---|---|
| 深色面 | `#181818` / `#212121` | Sidebar `#181818`、Canvas `#212121` | ✅ 一致 |
| 浅色面 | — | `#FFFFFF` / `#F9F9F9` / `#ECECEC` | 补上了浅色 |
| 次级文字 | `#a6a6a6` | `#B4B4B4` | 同一档，差 4% |
| 三级文字 | `#767676` | `#707070` | ✅ 基本一致 |
| 主文字 | `#f7f7f7` | `#ECECEC` | 同一档，差 4% |
| 蓝 | `#3a83f7` | `#2A7FFF` | 同色相，不同明度 |

**两个独立方法撞出同一批值，说明这些数字是这套设计语言的硬事实，不是我的幻觉。**
这是`quiet-dark` 最有力的一条外部证据，比任何"我觉得好看"都硬。

### 2. "不要纯黑"的理由，比我写的更具体

我写的是"纯黑会让圆角边缘和阴影糊成一团"。它写的是：

> `Don't make the canvas pure black (#000) — use #212121`

并给了 ChatGPT 的实际做法：深色画布 `#212121`，侧栏 `#181818`（**侧栏比画布暗**），
选中态 `#2F2F2F`，分隔线 `#424242`。

**注意这里有个和 Codex 相反的地方**：ChatGPT iOS 是「侧栏比画布暗」（`#181818` on `#212121`），
Codex 桌面是「侧栏比画布亮」（`#131313` on `#0d0d0d`）。两个都对——iOS 的侧栏是从画布上"推开"，桌面的侧栏是"嵌进去"。
→ 已写进 `quiet-dark/DESIGN.md` 的 Known Gaps：侧栏明度方向要按平台定，不是全局规则。

### 3. 组件级的观察，可以直接借的三条

- **用户消息有气泡，助手消息没有气泡。** 助手是一条"文档流"，不是一坨气泡。这是"对话即文档"的具体实现，我原来在 codex.html 里给用户消息做了卡片（对的），但没意识到**助手侧必须彻底无容器**。
- **发送按钮的尺寸只有 32pt，是个实心圆。** 空输入时它不可见，换成一行工具图标；有输入才出现。这是"状态驱动 UI"而不是"常驻 UI"。
- **侧栏按 Today / Yesterday / Previous 7 Days / Previous 30 Days 分组。** 我在 codex.html 里用的是"今天 / 昨天"，同一套逻辑。

## 弃

- **`#212121` 当深色画布。** 它是 **ChatGPT iOS** 的画布。Codex 桌面版真的更黑（`#0d0d0d`），我抠过。
  两者不能互换：iOS 在手机上、环境光强、屏幕小，`#212121` 更稳；桌面在暗房里、屏幕大，`#0d0d0d` 更沉浸。
- **Söhne 字体。** 商用授权字体（Klim Type Foundry），个人库里不能默认它存在。我只保留系统字体那一档。
- **voice mode 的蓝色球体。** 那是 ChatGPT 的签名动效，不是这套静默语言的组成部分。它整套都是静止的，唯一一个会动会发光的东西是那个球——**它是例外，不是规则**。照抄会把"安静"毁掉。
- **它完全没有 spacing / radius 的数值。** 466 行里 `border-radius` 只在"Border Radius Scale"一段出现，没有一处可以写成 token 的间距阶。这份文档能教你"气质"，教不了"实现"。→ 这是它和 `quiet-dark/DESIGN.md` 最大的差距：后者每个值都能落进 CSS。

## 待观察

- 它的 `DESIGN-swiftui.md` / `DESIGN-android.md` 我没抓。如果以后要做移动端，这三份是现成的平台映射（同一个设计语言在不同平台上的等价物）。
- 它的「Motion」一节写得很细（每条动效的时长和缓动都有）。本库四个风格都没有动效规格，这是共同的空白。要不要补，看是否真做交互。
