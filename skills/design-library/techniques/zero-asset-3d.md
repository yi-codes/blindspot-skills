# 零素材 3D：没有美术资源，也要一个真的场景

> 这条技法解决一个具体的处境：你想要一个真 3D 的场景（会转、有光、有前后），
> 但你手上没有模型、没有贴图、没有美术，也不想引入外部资源、不想让人下载 40 MB。
>
> 答案是：**几何和纹理都现算。** 一张 1024×1024 的 canvas、二十行顶点数据，
> 加上一盏算对了的灯，足够撑起一个房间。
>
> 本文来自 `clocktower-online` 的 3D 改造（一个血染钟楼式的桌游网页）。
> 里面每个数字都是跑出来的，不是查出来的。

---

## 一、先确定：这活该不该用 3D

不是"能做成 3D 就做成 3D"。问三个问题：

| 问题 | 该做 | 不该做 |
|---|---|---|
| 场景里有**互相穿插**的物体吗？ | 有 → WebGL | 只有前后关系 → CSS 3D 就够 |
| 相机需要**动**吗（绕转、缩放、视角切换）？ | 需要 → WebGL | 固定机位 → CSS 3D 或预渲染 |
| 文字是阅读主体吗？ | 是 → 别把字画进纹理 | 只是少量标签 → 画进纹理更省事 |

CSS 3D 的边界（按质心排序、无深度缓冲）写在 `styles/tactile-3d/DESIGN.md` 的 Elevation & Depth ⑥。
一句话复述：**牌的下半截在桌面之前、上半截在桌面之后，CSS 3D 表达不了。**

三条都指向 WebGL，再往下看。

## 二、几何：从立方体往上长，不追求"模型"，追求**剪影**

零素材的几何不是"简化版建模"，是另一套做法：**每个物体只由能读出它是什么的最少块数组成。**

桌游场景里真正够用的四个物体：

```
桶   = 圆柱 + 3 圈箍（细圆柱）
       r=0.42 h=0.95，箍在 y=0.22/0.48/0.74，半径 ×1.03
箱   = 立方体 + 4 条边框（薄立方体）
       0.9×0.7×0.9，边框宽 0.06，贴在前四个棱上
烛台 = 底座圆柱 + 杆 + 火焰（小球 + PointLight）
       底座 r=0.16 h=0.05，杆 r=0.03 h=0.5
椅   = 5 个立方体（坐面 1 + 腿 4）
```

四个物体、十五个网格，加一张地面，就能读成"一个房间"。再往上加东西的边际收益极低——
玩家读的是**布局**和**光**，不是物件细节。

**比例是唯一需要认真的地方。** 一张 2m 长桌在场景里是 9 个单位，那么：
- 牌（卡牌）1.30 × 1.74 单位 ≈ 真实扑克牌放大 2.5 倍——**必须放大**，否则在 1440×900 下只有 40px 宽，读不出名字。
- 桶高 0.95 单位 ≈ 真实 21cm。太矮看不见，太高会挡住桌面。
- 矮墙高 1.15–1.65 单位。这个高度范围是有讲究的，见第四节。

## 三、纹理：canvas 画，不下载

每个材质一个 `OffscreenCanvas`（或普通 canvas），`CanvasTexture` 贴上去。
1024×1024 是甜点：2048 视觉上没区别但生成要 4 倍时间，512 在近平面上会糊。

四种材质的配方，都是"底色 + 噪声 + 一笔特征"：

**纸（卡牌、书页）**
```
底色 #3b3122 → 一条 105° 的暖色渐变（左上亮，右下暗约 12%）
260 笔纤维：随机位置、长度 8–60、alpha 0.02–0.05、颜色在 #efe0c4 / #7a6a52 之间抖
四角压暗：radial-gradient 到 rgba(0,0,0,0.10)
```
纤维数量是关键——少于 150 笔看起来是脏，多于 400 笔会糊成灰色噪点。

**木（桌面、地板）**
```
底色 + 年轮：每隔 18–34 px 一条曲线，贝塞尔控制点抖动 ±6，alpha 0.05
纵向纹理：每 3 px 一条 1px 竖线，alpha 0.015（几乎看不见，但少了就是塑料）
重复 repeat.set(5, 5)，接缝处用 `wrapS = wrapT = RepeatWrapping`
```

**石（地面、墙体）**
```
不规则多边形铺装：每块 90–140px，随机旋转 ±4°，缝隙 3px 用 rgba(0,0,0,0.55)
每块独立亮度抖动 ±8%——统一亮度会像瓷砖，不像石板
```

**布（桌面、座位）**
```
底色 + 双向 weave：横竖各 1px 线，间隔 4px，alpha 0.03
```

一个必踩的坑：**`applyScene()` 里重新赋值 `material.map` 会把你在外部改过的贴图覆盖掉。**
我们的墙"涂成纯红但画面没变"查了两轮，第一次就是这个原因。
要么在 `applyScene()` 内部改，要么改完之后不要再调它。

## 四、光：三个必须知道的数

### 1. three.js r155 之后灯的单位变了

这是"第一版渲染全黑"的唯一原因。r155 起默认 `useLegacyLights = false`，
`SpotLight(color, intensity, distance)` 的 intensity 按**坎德拉**算，并且按 `decay = 2`（距离平方）衰减。

老习惯写 `new SpotLight(0xffd8a2, 1.5, 30)`，光在 15 个单位外只剩 `1.5 / 225 ≈ 0.007`——等于没有。

两种解法，选一种：

```js
// A. 关掉物理衰减（推荐，数值好调）
new THREE.SpotLight(color, 3.3, 0, 0.72, 0.85, 0)
//                                            ↑ decay = 0

// B. 保留物理衰减，把 intensity 拉到几十到几百
new THREE.SpotLight(color, 60, 40, 0.72, 0.85)
```

**排查顺序**（全黑时按这个顺序，别猜）：`decay` → `intensity` → `toneMappingExposure`（1.28 是个好起点）→ `AmbientLight` 是否真的加进了 scene。

### 2. 光有"够得着的范围"，超出就不亮

一本书举到镜头前 5.6 个单位处——它已经离开了顶光的锥体。翻开的书是两块黑板。

修法不是加灯（加灯会把整个场景照亮），是**让这个物体自己发光**：

```js
new THREE.MeshStandardMaterial({
  map: pageTex,
  emissive: 0xffffff,
  emissiveMap: pageTex,     // 同一张图：字亮、纸暗，不会糊成一片白
  emissiveIntensity: 0.62,
})
```
再挂一盏小的 `PointLight` 在物体组上，随物体一起飞。

### 3. 俯视角看不见墙——这是算术，不是审美

46° 相机仰角 + 40° 垂直视场角，画框覆盖的是**地平线以下 12°–52°**。
任何立起来的、高过视平线的东西，都在画框**之上**。

所以俯视角场景的房间**不靠墙讲**，靠三样东西：

| 手段 | 具体做法 | 为什么有效 |
|---|---|---|
| 地面材质 | 石板 / 木板 / 布，`repeat.set(5,5)` | 地面永远在画框里 |
| **矮**物件 | 桶 0.95、箱 0.7、烛台 0.55 | 越矮越靠画面下方，不会被裁掉 |
| 断墙 | 26 块，高 1.15–1.65，半径 r=15.2 | 高度刚好在画框下沿，读得出"这里有过墙" |

这条不只是"高东西看不见"。它解释了一个更普遍的现象：
**暗黑、哈迪斯这类俯视角游戏都用地面细节交代环境，不是因为他们不想做建筑，是因为俯视角看不到建筑。**

（还有一个反例：柱子。我们在 r=13 处放了四根 h=5.2 的柱子，它们唯一可见的部分是**柱底**——
但柱底加地面阴影已经足够暗示"这里是室内"。高物体只贡献它的落脚点。）

## 五、诊断：怎么确定某块东西到底在不在画面里

靠猜会浪费一整天。两个可靠手段：

**① 涂色实验。** 把材质设成纯红 `0xff0000`（`MeshBasicMaterial`，不参与光照），截图，比像素。
变了 = 在画面里但太暗；没变 = 根本不在画框内或被裁了。

**② 像素计数。** 截两张图（改前 / 改后），逐字节比。我们用这个方法确认了两次"墙纹丝不动"。

配套一个截图工具（`/tmp/shot/webgl.mjs` 的形态）：
Chrome `--headless=new --use-angle=metal --enable-unsafe-swiftshader`，
`Emulation.setDeviceMetricsOverride` 固定 1440×900，
轮询 `window.__ready`，同时捕获 `Runtime.consoleAPICalled` 和 `Runtime.exceptionThrown`。
**必须固定视口尺寸**——否则每次截图构图不同，对比像素就没有意义。

页面里留这几个 URL 参数，让每个状态都能单独截图，而不是靠点：
`?scene=0..3`（换场景）、`?night=1`、`?open=1`（书翻开）、`?seat=3`（高亮某人）。

## 六、和 sharecode 托管的关系

这套做法的副产品很值钱：**纹理是 canvas 画的，所以没有子资源。**

一个 sharecode 门禁下的静态托管，每个子资源请求都要带 `?sharecode=`：
`/tokens.css` 会 403，`/tokens.css?sharecode=xxx` 才 200。
而 HTML 本身永远 200——**所以"发布成功"和"页面正常"是两件事，必须逐个 curl 子资源。**

零素材 3D 天然绕开这件事：一个 HTML 里内联全部 CSS 和几何数据，只有 `three.module.min.js` 是外部文件
（要么也内联，要么走项目的 `scripts/sharecode-assets.mjs` 注入）。
没有任何图片、字体、模型要处理。

**一旦你开始下载 PNG 贴图，这个优势就没了。** 这也是"用 canvas 画纹理"除了省事之外的第二个理由。

## 七、交付前的验收清单

- [ ] 每个场景预设都换**四样**：雾、环境光、主光颜色、地面/木/石的色调。只换灯会读成"同一个房间换了灯泡"。
- [ ] 立面物体没有被画框裁掉（涂色实验过一遍）。
- [ ] 举到镜头前的东西有 `emissiveMap`。
- [ ] 相机有方位角 / 仰角 / 距离三个**下限和上限**，不是自由飘（`CAM_EL_MIN = 0.42, CAM_EL_MAX = 1.20`）。
- [ ] 没有 billboard。要读背面，就得绕过去。
- [ ] 每个物体都能读出是什么——把截图缩到 30% 再看一遍，认不出就是剪影没做好。
- [ ] `window.__ready` 在首帧后置位，方便自动截图。

## 已知边界

- **没有阴影贴图。** `SpotLight.castShadow` 能开，但每个投影物体要多渲染一遍，二十个物件就开始掉帧。目前的阴影全是假的（`MeshBasicMaterial` 的贴地圆片）——在俯视角里够用，换个机位就露馅。
- **没有 PBR。** 全部是 `MeshStandardMaterial` 的默认粗糙度 1.0，没有金属度、没有环境贴图。想做"湿石头"或"抛光木头"得另加一套。
- **中文只能画进 canvas。** 卡牌上的名字是 `fillText` 画的，所以不可选中、不可搜索、不能被读屏软件读到。真要做可访问，得在 3D 上层叠一层 HTML。
- **几何是手搓的。** 十五个网格还行，五十个就得写生成器。
- **这一套面向 PC。** 触屏上的拖拽相机、双指缩放、性能降级都没有做。
