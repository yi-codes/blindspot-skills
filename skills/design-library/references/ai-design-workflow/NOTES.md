## 弃

| 明确不吸收 | 原因 |
|---|---|
| **9/10 评分体系** | 库里已有"lint 通过 ≠ 设计成立"。再叠一个主观分数会让 build 产出变成不可比的数字；且实测同一张图跨会话分数漂移、会让两个 Agent 无限 loop。只作内部收敛信号，不进 lint、不进验收门槛 |
| **随机种子写进 `DESIGN.md` front matter** | 种子是一次性探索燃料，不是风格属性。写进契约会污染 24 个风格，也让 lint 的六层字段失去语义 |
| **发散产物直接进 `styles/`** | 违反 `principles.md` §8「只有必须违反现有硬约束才新开」和 §9「只吸收能写成数值的东西」。先过六层字段 + lint + §11 自查 |
| **拿 SSoT 论文给"随机串能出好设计"背书** | 论文验证的是概率指令跟随 (PIF) 与输出多样性 (DAG)，**没有验证网页设计质量、可用性或审美**。且这里改成外部 shell 随机源后机制已不同 |
| **把原文的技巧 7/8 细节写全** | 付费墙后只有二手转述，没有一手正文。宁缺勿编 |
| **把流程派当成契约派的替代** | 两条路线是上下游：流程派解决"从 0 到 1"，契约派解决"第 1 次到第 N 次不走样"。用流程派替换掉固化风格和 lint，会丢掉本库最硬的跨会话一致性 |
| **视频生图 / 生成媒体当常规动作** | 本库当前没有媒体生成能力，也不固定任何付费平台。只把"媒体要有职责和降级"写成判据，不写工具链 |
| **照搬 oil-ui 的风格对比页与 117 个案例** | 那是另一个 skill 的产品形态，不是可迁移的规则；本库已有 `catalog/` 承担比较职责 |

## 待观察

- 种子提示**跨模型不通用**：有实践者报告某些 Agent 直接要求"独一无二、所有设计决策随机"比字符串更有效，字符串反而限制了发挥。脚本输出的是起点，不是必须照抄的咒语。
- `REVIEW.md` 的独立评审在本环境里能否稳定委派子 Agent、评审输出是否可比，尚未跑过端到端验证。
- 长文技巧 7「Remove AI tells」的完整清单一手未读；本库 `principles.md` §11.2 已有 12 条，可能更全，待拿到原文后比对。
- 第 5 层两条媒体判据目前是**文档判据**，没有进 `lint.py`。是否要硬化成可检查字段，等用过几轮再决定——加字段会让全部风格报错，代价要单独评估。
