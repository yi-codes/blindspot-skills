# 探索：库外的方向从哪来

> 这一页回答一个问题：**24 个风格都用不上、或这次想试试没见过的方向时，怎么办？**
> 答案不是"让 AI 自由发挥"，而是从模型外部注入一次变化，再让产物回到契约里受审。

---

## 为什么库里需要这个动作

本库走的是**契约路线**：预先固化风格、六层必填字段、`lint.py` 硬校验。
它解决的是"任何一次都别掉回平均值，且跨页面跨会话一致"。

它没有解决"**从 0 到 1 找到方向**"。风格是人工精选后固化的，库里没有一个
"这次要不要试试库外"的入口。结果是要么硬套一个不合适的风格，要么临场让模型
自由发挥——后者几乎必然回到紫渐变、左文右图三张卡。

原因在 [`../principles.md`](../principles.md) §11 已经写透了：LLM 是 next-token
predictor，每个设计决策都填"最可能讨好多数人"的 token，再被人类偏好回灌强化。
于是默认输出是**训练分布的统计中位数**。

关键结论：**让模型"随机一点"没有用。** 它填的仍是一串听起来随机、实际仍落在
同一个风格家族里的高概率 token。变化源必须来自模型之外。

## 动作

```bash
python3 scripts/explore.py --task "独立开发者的作品集首页"
python3 scripts/explore.py --count 5 --json
python3 scripts/explore.py --seed <hex>   # 复现同一轮
```

脚本用 `secrets.token_hex()` 生成一串**外部**十六进制字符，输出一段可复制的探索提示词。
它不调模型、不写文件、不生成页面，只提供变化源和结构约束。

### 提示词要求的四件事

1. 从字符串里找能转成设计规则的**结构**：重复模式、字符形状、特殊数字、节奏
2. 给出 2–8 个**结构上不同**的方向，差异必须落在构图骨架、信息组织、字体类别、
   交互隐喻这四根轴上
3. **只换主色、圆角或插图不算不同方向**——那是换皮，是本库最想避开的结果
4. 每个方向先自检 `principles.md` §11.2 的「一眼假 12 条」和 §11.1 的 Specificity，
   命中 3 条以上、或遮住产品名仍站得住的直接划掉

### 发散不能越过的下限

`explore` 是**发散**，不是豁免。The Floor 那 12 条照旧生效：token 不写裸值、
一页一风格、不用紫蓝渐变、中文行高、焦点可见、reduced motion。

大胆要落在清晰的设计选择上，不能牺牲可读性、导航或关键操作。
一个方向如果听着很安全，它大概率会退回平均答案；让你怀疑"这能做成网页吗"的，
才真正在拓展边界。

## 产物怎么回库

```text
外部种子 → N 个结构不同的方向 → 人选一个 → 写 brief
   → 实现 → 真实截图 + REVIEW.md 独立评审 → 做减法
   → 能写成 {token} 或可检查规则的，进 references/ 候选池
   → 只有"必须违反现有风格硬约束"的，才走 ADDING-A-STYLE.md 进 styles/
```

**三条规定**：

1. **种子是一次性判断燃料。** 不进 `DESIGN.md` front matter，不进长期记忆，
   不出现在产品里。要复现就把它存进本次任务产物，不是存进风格定义。
2. **只有能被验收的东西才沉淀。** 判据见 [`../references/README.md`](../references/README.md)：
   能写成 `{token}` 或可检查规则 → 吸收；只能形容成"高级/未来感" → 留在 references
   当灵感，不进 styles。
3. **发散产物仍受契约管。** 新方向要能填满 [`../LAYERS.md`](../LAYERS.md) 的六层字段、
   过 `lint.py`、过 §11 自查，才配成为风格。发散不是绕过 lint 的捷径。

只换色、换字号或"想试试新感觉"，仍按 `principles.md` §8 修改现有风格，**不新开**。

## 必须先说清的边界

借的是 Sakana AI《String Seed of Thought》(arXiv:2510.21150, ICLR 2026) 的思路，
但下面三条不能含糊：

| 边界 | 说明 |
|---|---|
| 论文证明了什么 | 随机串能改善**概率指令跟随 (PIF)** 和**输出多样性 (DAG)**，且不牺牲任务质量 |
| 论文没证明什么 | **没有验证网页设计质量、可用性或审美**。拿它给"随机串能出好 UI"背书是过度外推 |
| 这里的机制已不同 | 原论文让模型内部生成串并做确定性变换；这里改成 shell / `secrets` 提供**外部**串，再让模型从字符里找灵感。两者都在打散默认偏好，但不是同一个机制 |

换句话说：`explore` 能证明的只是"**候选空间变宽**"，不自动证明设计更好。
变宽之后好不好，由 [`REVIEW.md`](REVIEW.md) 的评审和人来决定。

## 两条实测过的风险

- **跨模型不通用。** 同一套种子提示在不同 Agent 上效果不同；有实践者报告
  某些模型反而是直接要求"独一无二、所有设计决策随机"更有效，字符串反而限制了发挥。
  脚本输出的是起点，不是必须照抄的咒语。
- **别把失败的大胆提示丢掉。** 今天做不出来的方向，新模型发布后重跑一次可能就成立了。
  存进本次任务产物，那是观察模型能力边界最便宜的办法。
